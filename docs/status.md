## 테스트 범위

- **단위** (`tests/unit`): 권한 판정, 입력값 검증, 태그 정규화, LIKE 이스케이프, 오픈 리다이렉트 방지, Markdown XSS 제거/구조 보존, 파일 형식·크기·MIME·zip bomb·UTF-8 검증, docx/Markdown 파싱, 하이라이트 앵커(정확/재배치/중복 문장/복원 실패/범위 병합)
- **통합** (`tests/integration`, 실제 DB): 게시글 CRUD·권한, 비공개 글 접근 제어(조회/검색/태그 집계), 관리자 숨김, 검색(제목/작성자/태그/조합/와일드카드/SQL 문자열)·인기순·페이지네이션·관련 글, 댓글 CRUD·권한, 하이라이트 저장/중복/검증/소유권/본문 변경 후 복원 실패/비공개 전환, 알림 생성·읽음, 신고, 회원가입 API 차단(직접 호출 + HTTP), 관리자 계정 발급·로그인·정지·권한 변경
- **E2E** (`tests/e2e`, 실제 브라우저 + 프로덕션 빌드): 명세 11장 사용자 흐름 1~9 전체, Word 업로드 → 비공개 → 타인 404, 비로그인 제한과 `/signup` 부재, 관리자 계정 발급 → 새 계정 로그인, 모바일 가로 스크롤 없음

## 개발 중 발견하고 수정한 문제

1. Next.js 16.4.0 critical 취약점 → 16.4.3 으로 업그레이드
2. JOIN 이 없는 쿼리에서 Drizzle 이 상관 서브쿼리의 바깥 컬럼을 한정하지 않아 관리자 사용자 목록이 실패 (`text = uuid`) → 모든 상관 서브쿼리를 명시적으로 한정하고 회귀 테스트 추가
3. 비공개 글이 `loading.tsx` 스트리밍 때문에 HTTP 200(내용은 노출되지 않음, noindex)으로 응답 → 상세 경로에서 loading UI 제거, 404 확인
4. 하이라이트 저장 메시지가 스크린 리더에 두 번 읽히던 문제 수정

## 알려진 제한 사항

- Word 문서의 이미지와 표 서식은 가져오지 않는다.
- 하이라이트 표시는 CSS Custom Highlight API 를 지원하는 브라우저에서만 본문에 칠해진다(미지원 시 목록만).
- 조회수는 수집하지 않으며 인기 정렬은 전체 기간의 댓글 수 기준이다.
- rate limit 은 메모리 기반(단일 인스턴스 전제).
- 이메일 초대·비밀번호 재설정 메일은 없다(관리자가 비밀번호를 재발급하려면 현재는 Better Auth admin `setUserPassword` API 를 직접 써야 함 — UI 미구현).
- 다크 모드 없음.
- 실제 배포는 하지 않았다.
