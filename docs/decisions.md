# 설계 결정 기록

### D-01. Supabase 대신 PostgreSQL(Docker) + Drizzle + Better Auth
- **배경**: 빈 저장소, Supabase 프로젝트·자격 증명 없음. 프롬프트는 "Supabase 또는 동등한 관리형 솔루션"을 권장.
- **결정**: 로컬에서 바로 재현 가능한 PostgreSQL 16(Docker) + Drizzle ORM(타입 안전한 쿼리, SQL 마이그레이션) + Better Auth(검증된 인증 라이브러리, 자체 호스팅).
- **결과**: 외부 계정 없이 실행·테스트 가능. 배포 시 관리형 PostgreSQL(Neon, RDS, Supabase DB 등) 어디든 연결 가능. RLS 대신 서버 계층에서 권한을 검증하고 통합 테스트로 확인한다.

### D-02. 회원가입 없음, 관리자 발급 계정
- 기존 정책이 없으므로 "관리자가 생성한 계정" 방식을 채택. `emailAndPassword.disableSignUp: true` 로 가입 API 자체를 막고(테스트로 확인), 계정은 관리자 페이지 또는 `npm run admin:create` 로만 생성한다.
- 이메일 초대(링크) 방식은 메일 발송 서비스 설정이 필요해 보류.

### D-03. 본문 저장 형식은 Markdown, 원본 파일은 보관하지 않음
- docx 와 md 를 하나의 정규화 형식(Markdown)으로 통일 → 웹 표시 안정, 수정 화면에서 직접 편집 가능.
- 원본 파일 보관은 중복 저장과 개인정보(문서 메타데이터 등) 위험이 있어 하지 않는다. `source_file_path` 컬럼만 확장용으로 둔다.

### D-04. HTML 은 저장하지 않고 요청 시 렌더링
- sanitize 규칙을 바꾸면 과거 글에도 즉시 적용된다. 렌더링 비용은 MVP 규모에서 무시할 수준.

### D-05. Word 이미지·표 서식 미지원
- 이미지는 용량·저장소 설계가 필요해 MVP 에서 제외(업로드 화면에 안내). 표는 텍스트로만 남는다.

### D-06. 하이라이트 표시는 CSS Custom Highlight API
- `<mark>` 를 DOM 에 끼워 넣으면 React 가 관리하는 DOM 과 충돌하고 오프셋 계산이 복잡해진다. Highlight API 는 DOM 을 바꾸지 않는다. 최신 Chrome/Edge/Safari/Firefox 지원, 미지원 시 목록으로 대체.

### D-07. 이모지 반응 (제거됨)
- 요구사항의 "기존 반응 변경"과 "사용자·게시글 기준 중복 방지"를 함께 만족하도록 UNIQUE(post_id, user_id) + upsert.
- 2026-10-27: 반응 종류를 ✅ 하나로 축소. 기존 반응은 삭제하지 않고 ✅ 로 변환(마이그레이션 0002). 
- 2026-10-27: 사용자 요청으로 반응 기능 자체를 제거. 마이그레이션 0003 에서 `reactions` 테이블과 반응 알림을 삭제했다. 인기 정렬은 댓글 수 기준으로 바뀌었다. 다시 도입하려면 테이블·서비스·UI 를 새로 추가해야 한다.

### D-08. 비공개 글은 관리자도 본문 열람 불가
- 개인정보 최소 노출. 관리자는 메타데이터 확인과 숨김/삭제만 가능. 신고는 타인이 볼 수 있는 공개 글에서만 발생하므로 운영에 지장 없음.

### D-09. 접근 불가 리소스는 404
- 비공개 글·타인 하이라이트에 403 을 주면 존재 여부가 드러나므로 404 로 통일. 글 상세는 `loading.tsx` 스트리밍 시 상태 코드가 200 이 되므로 상세 경로에는 loading UI 를 두지 않았다.

### D-10. 의존성 설치에 `legacy-peer-deps`
- npm 10.9 에서 vitest 5 의 선택적 peer 의존성 해석 중 arborist 오류(`Cannot read properties of null (reading 'edgesOut')`)가 발생해 `.npmrc` 에 설정. 대신 `vite` 를 devDependency 로 명시했다.

### D-11. Next.js 16.4.3
- 처음 16.4.0 으로 구성했으나 `npm audit` 에서 16.0.0~16.4.0 대상 critical 취약점(이미지 최적화·`use cache` RCE, 서버 액션 DoS)이 확인되어 패치 버전 16.4.3 으로 올렸다.

### D-12. React Hook Form 미사용
- 폼이 단순해 상태 관리 라이브러리 없이 Zod 스키마를 클라이언트·서버에서 공유하는 방식으로 충분했다. 의존성을 줄이기 위해 추가하지 않았다.

### D-13. 메모리 기반 rate limit
- 단일 인스턴스 전제. 수평 확장 시 Redis 등 공유 저장소로 교체 필요.

### D-14. 테마는 CSS 변수 묶음 + 사용자 선택(라이트/다크)
- 모든 색·본문 글꼴을 디자인 토큰(CSS 변수)으로 두고 `<html data-theme>` 로 묶음 전체를 교체한다.
- 후보 4종(따뜻한 종이, 먹과 여백, 숲길, 밤의 서재)을 비교한 뒤, 2026-10-27 요청에 따라 라이트=먹과 여백, 다크=밤의 서재 두 가지를 사용자가 헤더에서 전환하도록 했다. 선택은 쿠키에 저장해 서버 렌더링 시점부터 깜빡임 없이 적용된다. 자세한 내용은 docs/theming.md.

### D-15. 배포 대상 추천: Railway (앱 + PostgreSQL)
- 현재 구조(상시 실행 Node 서버, pg 커넥션 풀, 메모리 rate limit, 5MB 업로드)를 코드 변경 없이 운영할 수 있고, 관리 화면이 하나라서 운영 경험이 적은 팀에 맞다. Vercel + Neon 은 대안 (docs/deployment.md 6장).
- `tsx`, `dotenv` 를 dependencies 로 옮겨 배포 서버에서도 `db:migrate`, `admin:create` 를 실행할 수 있게 했다.
